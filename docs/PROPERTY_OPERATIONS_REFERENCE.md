# 住宅物业维修运行参考与产品适配

更新：2026-09-09。

本文件记录 FixFlow 参考的公开物业运行规则及其产品含义。它不是法律意见，也不把某一城市、某一合同或某一服务商的时限冒充全国统一标准。当前 `data/policies/fixflow_demo_policies.json` 仍是合成演示语料；正式部署必须由目标小区确认适用地区、物业服务合同、管理规约、收费与责任边界后导入正式政策。

## 住户最小输入

普通住户能够合理提供的信息是：

- 哪个房间或大致位置有问题；
- 看见、听见或闻到的现象；
- 是否存在水、电、烟、焦味、被困人员等即时风险；
- 方便上门的时间。

以下信息不得作为创建普通报修的前置条件：

- 品牌、型号、具体零件名称；
- 管线、电路或锁体的精确结构；
- 故障根因；
- 维修方法、材料或预计工时。

例如“书房的开关坏了”“卫生间洗手池下面滴水”“卧室门锁经常锁不上”已经包含类别线索、可行动的位置和可观察现象。系统可以继续询问可上门时间或真正缺失的安全信息，但不能把专业诊断责任转嫁给住户。

## 确定性运行规则

1. 先验证住户和房屋关系，再检索政策或写入业务事实。
2. 安全信号优先于普通预约；有触电、冒烟、持续大量漏水、人员被困等风险时停止自动预约并创建人工处理任务。
3. 普通报修以房间级位置和可观察现象为最低可行动信息，不要求精确设备资料。
4. 自动系统只做已冻结的漏水、电气和门锁分类；未知类别或证据不足转人工，不编造工单内容。
5. 候选时间不是预约承诺；只有事务提交成功后才显示预约成功。
6. 维修人员声明完成不等于住户验收；未解决的问题保留原工单返工事实。
7. 责任主体、价格、赔偿、专项维修资金和合同覆盖范围未获得可靠政策证据时，不自动承诺，由物业人工核对。
8. 每条住户消息必须进入完成、等待住户选择、失败或已转人工之一，不能长期空白。

## 政策数据适配边界

正式小区接入时，政策管理员至少应提供：

- 来源机构、公开或内部文件编号及可追溯引用；
- 适用小区/地区与服务合同版本；
- 生效、失效时间；
- 服务范围、责任边界、紧急等级和响应承诺；
- 收费或维修资金需要人工确认的边界；
- 修订人与审批记录。

当前 Policy Schema 能保存来源、版本和有效期，但没有独立的 jurisdiction/contract-scope 字段。首版因此继续把真实部署政策作为上线前人工治理事项，不为演示数据虚构适用范围，也不在本轮增加 Migration。
