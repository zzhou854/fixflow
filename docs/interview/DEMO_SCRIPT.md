# FixFlow 8 分钟现场演示脚本

## 演示目标

让面试官在 8 分钟内看到四件事：自然语言可用、业务写入可信、失败能够收口、物业能够接管。

## 演示前准备（不计入演示时间）

```powershell
cd F:\agent\fixflow
docker compose ps
powershell -ExecutionPolicy Bypass -File scripts\operations\verify.ps1
```

确认以下地址可访问：

- 住户端：`http://127.0.0.1:5173/resident`
- 物业端：`http://127.0.0.1:5173/operator`
- API 健康检查：`http://127.0.0.1:8000/health`

使用仓库 README 中的开发账号。不要在投屏、录屏或简历中展示 JWT、API Key、数据库连接串和 `.env`。

## 0:00–0:45：一句话介绍

> FixFlow 是一个住宅维修协调 Agent。它不是让模型直接操作数据库，而是让模型把住户的生活化描述转成有证据的结构化事实，再由确定性状态机、MCP 和事务服务完成工单与预约。今天我演示正常报修、预约以及失败后的人工接管。

同时指出顶部“服务试运行中”提示：当前在线模型是开发白名单能力，不冒充生产激活。

## 0:45–3:30：住户模糊报修与预约

1. 登录住户端并新建会话。
2. 输入：

   > 书房墙上的插座不太灵，我不知道具体是什么问题，明天上午家里有人。

3. 讲解观察点：

   - 用户只描述房间和可观察现象，不需要知道型号、零件或成因；
   - Flash 提取类别、位置、描述和时间证据；
   - 确定性代码决定必填项、风险、工单状态和 60 分钟服务时长；
   - “明天上午”由集中规则解释为当地 09:00–12:00；
   - 候选时间按 30 分钟粒度生成，界面最多显示 6 个；
   - `booking_guaranteed=false`，点击前只是候选。

4. 选择一个候选时间。
5. 等待页面显示“上门时间已经预约成功”。
6. 强调：只有 MCP 后面的 Application Service 在同一事务中成功写入工单、预约、历史和幂等结果后，界面才显示成功。

如果现场没有候选，不要编造结果。换一个未来可用时段；仍无候选则展示明确的无可用时间状态，并进入物业协助路径。

## 3:30–4:30：会话和产品体验

打开移动端抽屉或桌面侧栏：

- 最近只显示 5 条；
- “查看全部会话”可搜索和查看归档；
- “删除”实际是可恢复归档；
- 已关联工单的会话归档不会取消工单或预约；
- 输入框固定在聊天区底部，消息区独立滚动。

这部分用来说明项目不仅有后端可靠性，也处理了普通住户能否理解和操作的问题。

## 4:30–6:15：物业工作台与人工接管

1. 切换物业账号，进入“业务处理”。
2. 展示工单列表、业务中文状态和筛选。
3. 打开“待人工处理”队列，选择已有的受控故障验收任务。
4. 展示以下事实：

   - Flash 超时、限流、连接异常、5xx 或一次结构修复耗尽后，线程进入人工处理；
   - 工单创建前也可以创建 `human_review_case`；
   - 系统不会为了让物业看见任务而伪造工单；
   - 物业可以认领、记录处理说明并办结；
   - 同一线程、意图版本和失败阶段只产生一个未关闭任务。

不要现场故意关闭 API 或修改 `.env`。直接使用已经保留的受控故障证据，避免演示环境失稳。

## 6:15–7:15：技术审计

切换“处理依据”和“技术审计”，快速展示：

- Policy Evidence 与冲突/充分性是业务依据，不是模型指令；
- 状态历史不冒充 Agent Trace；
- Trace、Outbox、对账和 Replay 分属不同控制面；
- Replay 只使用捕获的结构化 Tape，禁止真实 Mutation、MCP、Provider 和正式 Checkpoint IO。

## 7:15–8:00：收束

> 这个项目最重要的不是组件数量，而是把概率模型限制在适合它的语言边界内，把权限、业务状态、事务和恢复留给确定性系统。正常路径能完成真实预约，失败路径能给住户明确结果并由物业接管，这也是我认为 Agent 应用从 Demo 走向工程产品的关键。

主动说明仍未完成的生产边界：新锁定 Holdout、Shadow/Canary、目标小区正式政策审批、TLS/监控/异地备份及正式运营排班。

## 现场故障备用方案

- 在线模型不可用：展示已保存的人工转交案例，并说明这是正式失败语义，不切 Scripted 冒充成功。
- Docker 不稳定：展示产品验收文档、架构图和数据库备份验证记录。
- 候选时间冲突：解释乐观锁、部分唯一索引和 GiST 排斥约束，换选另一个时间。
- SSE 断开：刷新 Thread State；HTTP 响应和状态查询才是正式结果，SSE 只是提示通道。
