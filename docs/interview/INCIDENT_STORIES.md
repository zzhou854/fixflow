# 三个可用于面试的故障复盘

以下故事适合用 STAR 结构讲解。重点是“如何建立证据链和修复边界”，不是声称从未出错。

## 故障一：用户发送消息后没有可靠回复

### Situation

真实浏览器测试中，模型传输失败时住户看到“线程上下文校验失败”，页面甚至可能长期像没有回复；但数据库里的 Agent Run 已经记录 `PROVIDER_EXHAUSTED`。

### Task

要求每条消息最终进入 `COMPLETED`、`FAILED` 或 `ESCALATED`，并且失败时物业必须可发现，不能靠 Scripted Provider 伪装成功。

### Action

1. 沿 `Frontend -> API -> Orchestrator -> Checkpoint -> Provider -> SSE` 逐层核对。
2. 发现 Orchestrator 的统一失败构造函数把所有错误都映射成身份冲突文案，且语言异常没有把可恢复状态持久化为人工处理。
3. 新增确定性失败路由：Provider/语言失败写入 `HUMAN_REVIEW`、清除待执行操作、保存原因和友好文案。
4. 通过 `human_review_cases` 创建工单前人工任务，不伪造工单。
5. 用浏览器强制连接失败，验证住户明确看到转人工，物业能够认领和办结。

### Result

线上候选失败后不再产生空白等待或错误身份提示。业务 Mutation 为零，但人工任务可追踪、可去重、可审计。

### 追问准备

- 为什么不自动回退 Scripted？因为这会把模拟结果冒充真实模型处理，破坏产品语义。
- 为什么不无限重试？因为高风险/语义冲突不是传输错误，多模型重试会增加延迟和不一致。
- 为什么人工任务可以没有工单？因为失败可能发生在建单前；可见性不能依赖伪造业务事实。

## 故障二：“明天上午”被展示成凌晨

### Situation

DeepSeek Flash 能正确识别电气报修，但某次把“明天上午”输出为当地 00:00 开始。Schema 和时区偏移都合法，所以纯结构校验没有发现语义错误。

### Task

既不能要求住户输入精确时间，也不能让错误候选进入预约界面。

### Action

1. 通过 Thread State API 确认错误来自结构化可用时间，而不是浏览器 `toLocaleString`。
2. 保留模型负责开放语言提取，但为常见、无歧义的相对日期 + 时段增加集中确定性解释：上午 09:00–12:00、下午 14:00–18:00、晚上 18:00–21:00。
3. 遇到明确钟点或混合时段时不覆盖模型结果，避免丢失用户精度。
4. 将住户候选数限制为最多 6 个，底层仍执行完整资格、冲突和排序检查。
5. 重新用真实浏览器输入模糊插座报修，观察到 09:00、09:30、10:00、10:30、11:00，并成功预约。

### Result

修复了 Schema 合法但业务语义错误的边界，同时保留普通住户的低输入门槛。

### 追问准备

- 为什么不只改 Prompt？Prompt 能降低概率但不能形成确定性保证；常见时段属于适合代码固化的产品规则。
- 规则是不是全球通用？不是。它是当前演示业务规则，正式站点要根据服务时间和政策配置化审批。

## 故障三：物业“标记已解决”按钮没有弹窗

### Situation

物业已经认领人工任务，但点击“标记已解决”无响应。浏览器控制台同时出现 React 19 下 Ant Design 静态 Modal 的上下文警告；SSE 断开还产生未处理的 `AbortError` 噪声。

### Task

修复真正阻断人工闭环的交互，同时避免把正常的连接取消报告成应用错误。

### Action

1. 在应用根节点加入 Ant Design `App` 上下文。
2. 把静态 `Modal.confirm` 改为 `App.useApp()` 提供的实例方法。
3. 在 SSE cleanup 中先 abort，再显式吸收 `reader.cancel()` 的预期拒绝。
4. 只运行受影响的组件和 Hook 测试，再用浏览器实际填写处理说明并确认。

### Result

确认弹窗恢复，物业任务成功进入“已解决”；SSE 正常断开不再制造未处理异常。

### 追问准备

- 为什么测试先前没发现？组件断言覆盖了函数行为，但没有覆盖真实 React 19 上下文和浏览器交互组合；因此补充浏览器纵向验收。
- 为什么不引入完整 E2E 平台？当前规模下，重点路径由 API 集成测试、组件测试和内置浏览器验收共同覆盖，引入新框架收益不足。

## 可选第四故事：会话列表把页面撑得很长

这是产品思维案例：不是后端 bug，但直接影响用户完成任务。解决方式是 100vh 固定框架、左右区域独立滚动、输入框固定、最近 5 条会话、全部会话抽屉、可恢复归档及移动端抽屉侧栏。说明工程质量也包括认知负担和下一步是否清晰。
